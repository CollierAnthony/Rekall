Architecture de Rekall

Une appli React publiée en artefact, construite en hexagone : un domaine pur au centre, des cas d’usage qui ne parlent qu’à des ports, et des adaptateurs choisis au démarrage selon ce que le runtime de l’artefact sert.

  • 4 couches
  • 5 ports
  • 7 adaptateurs
  • 3 400 lignes de TypeScript
  • 80 tests

Le schéma

Clique sur un bloc pour voir son rôle, ses fichiers et pourquoi il existe. Les flèches pointent toujours vers le centre : une couche ne connaît que celles qui sont plus à l’intérieur.

La règle de dépendance

Tout l’intérêt de l’hexagone tient en trois règles. Elles se vérifient en lisant les import en tête de chaque fichier.

Le domaine n’importe rien

Uniquement d’autres fichiers du domaine. Pas de React, pas de Zod, pas de ts-fsrs, pas de window. C’est pour ça qu’il se teste avec des dates et des objets en dur.

L’application ne connaît que des ports

TodayReview reçoit un Scheduler, un ProgressRepository… sans savoir s’il parle à FSRS, à la base de l’artefact ou au navigateur.

Un seul fichier connaît tout

composition-root.ts est le seul à importer à la fois les cas d’usage et les adaptateurs. Changer d’adaptateur, c’est changer une ligne ici.

Deux parcours dans le code

Le démarrage et la notation d’une carte traversent toutes les couches. Les suivre une fois suffit à comprendre l’appli.

Démarrage

  1. main.tsx appelle startApp() une seule fois, hors du rendu, et passe la promesse à <App>.

    compositionmain.tsx

  2. Le runtime de l’artefact est interrogé en parallèle : base + identité de l’utilisateur, et sample pour Claude.

    infrastructureartifact-runtime.ts

  3. Les adaptateurs sont choisis : base de l’artefact ou localStorage, correcteur Claude ou aucun.

    compositioncomposition-root.ts

  4. loadToday(now) charge en parallèle les decks (validés par Zod) et la progression ; la progression des cartes disparues est écartée.

    applicationtoday-review.ts

  5. composeTodayQueue place les cartes dues, puis les nouvelles deck par deck, dans la limite de 15 par jour.

    domainetoday-queue.ts

  6. <App> lit la promesse avec use() sous <Suspense>, puis rend Rekall.

    UIApp.tsx

Noter une carte

  1. Clic sur « Bon » (ou touche 3) dans le dock de notation.

    UIRatingDock.tsx

  2. Le hook de session appelle todayReview.rate(card, progress, 'good', now).

    UIuseTodaySession.ts

  3. Le port Scheduler calcule la nouvelle progression ; FSRS ne sort jamais de son adaptateur.

    infrastructurefsrs-scheduler.ts

  4. Le port ProgressRepository l’enregistre : un document par carte, validé par Zod.

    infrastructureartifact-db-progress-repository.ts

  5. Le reducer applique advanceTodayQueue : la carte repasse en fin de file si elle revient dans la journée.

    domainetoday-queue.ts

  6. Rekall se re-rend : l’accueil, la bibliothèque et l’entretien voient la nouvelle progression sans rechargement.

    UIRekall.tsx

L’interface

Pas de routeur ni de store global : un onglet courant, au plus un écran ouvert par-dessus, et la session du jour tenue au sommet par un useReducer.

  • AppErrorBoundary + Suspense, lit le contexte avec use()
    • RekalluseTodaySession · useAppNavigation · useReloadOnNewReviewDay
      • <Activity> ongletsmasqués mais montés : état et défilement conservés

Le contenu

Les decks sont des fichiers JSON publiés à côté de la page. Ajouter une techno, c’est un fichier et une ligne dans l’index, sans toucher au code ; un test fait passer chaque deck listé dans le même parseur que l’appli.

À challenger

Ce que je referais autrement, ou que je surveillerais, en relisant le code avec un œil exigeant.

  • L’UI lit le domaine sans passer par l’application

    cardStatus, searchCards, summarizeDeckProgress, isInterviewUnlocked sont appelées depuis les écrans. Ce sont des fonctions pures en lecture seule, donc sans danger, mais c’est un raccourci par rapport à un hexagone strict.

  • Les tests d’interface passent par l’appli entière

    Rekall.spec.tsx rend toute l’appli avec des adaptateurs en mémoire et la pilote par rôles et libellés. C’est robuste aux refontes visuelles, mais un échec pointe un parcours, pas un composant. Ne pas en multiplier les cas : les règles se testent dans le domaine.

  • Les types du runtime d’artefact sont écrits à la main

    artifact-runtime.ts décrit à la main la base, l’identité et sample. Si le contrat du runtime change, ce fichier est le seul à adapter, mais rien ne le signalera à la compilation.

Parcours de lecture

Un ordre pour lire le code demain, du centre vers l’extérieur. Compte une à deux heures.

  1. domain/deck.ts · domain/review.ts

    Le vocabulaire : Card (union discriminée sur kind), Deck, CardProgress, Rating.

  2. domain/today-queue.ts + today-queue.spec.ts

    La règle centrale : journée à 4 h, file du jour, deck par deck, quota. Lis les tests en même temps, ils racontent les cas limites.

  3. application/ports/*.ts · application/today-review.ts

    Ce que l’appli attend du monde extérieur, et le cas d’usage principal.

  4. composition-root.ts · main.tsx · ui/App.tsx

    Où tout est branché, et comment la promesse de démarrage arrive dans React.

  5. infrastructure/scheduling/fsrs-scheduler.ts

    Comment FSRS est enfermé derrière le port, avec son état validé par Zod.

  6. infrastructure/progress/* · infrastructure/deck-file/*

    Documents stockés, validation, et la différence base de l’artefact / navigateur.

  7. ui/Rekall.tsx · ui/shell/useAppNavigation.ts

    L’assemblage des écrans, <Activity> et le retour navigateur.

  8. ui/today/useTodaySession.ts · ui/today/ReviewSession.tsx

    La session de bout en bout, raccourcis clavier compris.

  9. ui/interview/* · infrastructure/grading/claude-answer-grader.ts

    Le mode entretien et la correction par Claude, avec son repli.

Lancer le projet

En local, la progression va dans le navigateur et la correction par Claude est remplacée par la grille : seul l’artefact publié a la base et sample.

# Node 24, depuis le dossier du projet
npm install
npm run dev              # http://localhost:5173
npm test                 # Vitest, 80 tests
npm run typecheck        # tsc --noEmit
npm run build:artifact   # artifact/index.html + artifact/decks, prêts à publier
